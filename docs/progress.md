## 2026-10-12 · 서비스 정의와 DB 1차 설계

- 카드고릴라 기준 카드 비교 DB 설계 → "내 소비 기준 실제 혜택액" 계산을 차별점으로 잡음
- 금융상품한눈에를 보고 아이디어 5개 비교 후 **카드 + 적금 묶음 추천**으로 확정
  - 이유: 적금 우대조건에 카드 실적이 자주 붙는데, 두 사이트가 이를 따로 보여줌
- 요구사항 12개를 명사(테이블)·동사(관계)로 분해, 테이블 13개와 PK 확정
  - PK는 인조식별자 기본. 복합키는 `user_spending(user_id, category_id)` 하나
  - `user_conditions`는 금융사 칸이 NULL일 수 있어 복합 PK 대신 번호 PK + UNIQUE
- 은행과 카드사를 `fin_companies` 한 테이블에 둠 → 적금 우대조건의 `card_company_id`가 카드사를 FK로 가리킬 수 있음

## 2026-10-16 · 실제 데이터 입력

- 금융상품한눈에 인증키 발급(금융결제원 오픈API와 다른 곳이라 처음에 헷갈림), 적금 59개·금리 옵션 178개 입력
- 우대조건 원문을 조건 하나당 한 줄로 분해 (12개 상품, 52줄, 카드실적 조건 10개)
  - 판단 기준
    - 누적 카드 실적(예: 300만 원)은 12개월로 나눠 월 금액으로 환산
    - "15%/10% 택1", "1~5%"처럼 범위는 낮은 값
    - 기준 금액이 없는 카드 조건은 0원(그 카드를 쓰면 충족)
    - 9개 중 6개 선택(KB내맘대로)처럼 선택 규칙은 표현 못 함 → 최고금리 상한으로만 제한
    - 신규/기존 고객 분기(경남은행 오면우대)는 신규 쪽만 반영
    - 항목별 금리가 없는 상품(케이뱅크)은 제외
- 카드 31장 입력(카드고릴라 화면 기준, 수업용)
  - 원 단위 혜택(대중교통 300원, 리터당 60원), 바우처, 마일리지는 % 계산이 안 돼 제외
  - '국내전체' 카테고리 추가: 업종 무관 혜택은 총지출에 적용하도록 VIEW 수정
- 데이터 출처 판단
  - 카드고릴라 자동 수집: robots.txt상 상세 페이지는 허용이지만, 경쟁 서비스 데이터를 공개 서비스에 쓰면 데이터베이스 제작자 권리·부정경쟁 문제 소지 → 수업용으로만 사용
  - 카드 상품 통합 공개 API 없음 → 공개 버전은 카드사 공식 상품설명서로 재정리
- 공개 서비스 방향
  - 2021년 금소법 시행 때 플랫폼의 비교·추천이 중개로 해석된 사례가 있음 → 첫 버전은 신청 링크·제휴 수익 없는 계산기
  - 로그인 없이 계산하고 입력값은 오래 보관하지 않는 구조
